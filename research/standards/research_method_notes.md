## 3. 1a–4b：分析、替换与归因

**定义来源已补齐。** 《问题清单》只写“1a-2b”；WF03 第1章附录及迁移章节给出了明确定义，因此不再将本仓库的该术语整体标为未定义。先前“待澄清”的记录保留为历史状态。

| 步骤 | 原文含义 | 要留下的证据 |
|---|---|---|
| 1a | 观察失败实验的现象 | 任务、条件、对照、原始日志/图表与不确定性 |
| 1b | 归类现象，寻找可能共同指向的根因 | 分组依据、差异、反例；共同根因暂为候选解释 |
| 2a | 继续追问更深层原因 | 竞争假设、最有区分力的测量或干预、待补证据 |
| 2b | 将原因串联成因果链 | 每条连接的 SC/DE/AI/UN、条件及替代解释 |
| 3a | 替换有问题的模块，检验是否有效 | 最小修改位置、计划与实际差异、对照结果 |
| 3b | 多处改动应尽量独立、互不影响 | 独立性依据；若存在交互，显式设计组合对照，不能假定独立 |
| 4a | 逐个添加/消融，量化单模块效果 | 公平预算、相同输入、重复与增益/代价 |
| 4b | 验证改动是否符合之前的问题分析 | 机制预测与实际观测是否一致，不只看总指标 |

原文建议不理想时回到前一步深入理解。执行时回补影响判断的关键证据，并记录为何继续/回退；不把“几乎完全了解”转成可以无限追问却不做检验的门槛。

这些步骤嵌入 Mode C、迁移、Idea 与实际验证；不能因使用 1a–4b 而绕过原始运行记录和深挖回流。

## 4. 科研死循环与实验弯路：逐条保留

原文描述的循环为：发现问题 → 设计方案 → 修复当前问题 → 引入新问题 → 再加方案。局部修复、系统净收益和新增知识应分别评价。

| 编号 / 原文章节 | 记录的想法 | 每次执行需要回答 |
|---|---|---|
| DL01 · 实验弯路一、三 | 局部问题解决，不保证整体性能改善；收益可能被副作用抵消 | 目标现象改善多少？整体目标、服务约束和成本如何变化？ |
| DL02 · 实验弯路二 | 根因分析面向已发生现象，方案副作用仍需实验；AI 不能可靠预见全部影响 | 哪些只是机制假设？什么观测能区分噪声、交互与真实副作用？ |
| DL03 · 实验弯路四；死循环一 | 增加机制会有系统代价；优先读类似问题的已有方法、结果和适用条件 | 有哪些相关方案/负结果？为什么当前条件适合借鉴？新机制增加什么代价？ |
| DL04 · 死循环二 | 能拆开时先单变量验证；强交互无法由单因素实验完全解释 | 本轮唯一变量是什么？如要测交互，组合对照如何设计和解释？ |
| DL05 · 死循环三 | 实验前同时指定预期局部改善、可能受损指标和最终去留指标 | 哪个整体指标/约束决定保留？局部到整体的传递链缺在哪里？ |
| DL06 · 死循环四 | 提前写明解决哪个问题、何时回退、回退后保留哪些观察 | 回退目标版本/配置是什么？触发条件是什么？运行与现象如何保留？ |
| DL07 · 死循环四 | 不能因已投入大量时间就继续堆机制；新发现可独立留下 | 是否有新证据支持继续？如果只是挽救已有投入，是否应回到稳定基线？ |
| DL08 · 死循环五 | 先定成功/停止判据；负结果也要说明学到什么 | 核心假设受到支持、反对还是证据不足？下一步排除什么？ |
| DL09 · 死循环五、六 | 未理解上次结果，不急着改下一版；不用 idea 数或运行次数充当研究进度 | 本次减少了哪项不确定性？下一项检查为什么能改变判断？ |

本仓库将这些项加入 Idea 和实验模板，结果记录后经 squeeze/Mode C 形成下一决策。回退针对代码与配置，保留失败运行和研究观察；没有整体收益不自动证明机制无效，也不自动证明方向毫无价值。

## 5. 跨领域论文方法迁移：完整思路

原文以领域 A 为目标、B 为源方法、C 为已有迁移案例；这里的 C 与 Mode C 连接点不同。

| 原文步骤 | 必须保留的思路 |
|---|---|
| 一、目标问题深挖 | 用 1a–2b 从现象追到可操作机制，多轮只在有新发现/有效检验时继续；AI 因果解释需要代码和实验核验 |
| 二、寻找 B | 以底层困难和机制检索，不限于同任务名称；找到后核原文，不只看摘要中的相同术语 |
| 三、B 为什么有效 | 分析原始缺陷、核心作用部分、生效条件及缺少条件时可能失效的范围 |
| 四、寻找 C | 比较输入输出、连接、目标和实现变化，分清接口适配、机制条件和工程选择；无现成案例不代表不能迁移，也不代表此前无人迁移 |
| 五、改造 A | 优先考虑怎样让 A 的 Baseline 产生 B 所需条件，明确 A′；不是仅把接口连起来。保留或修改 B 时解释机制 |
| 六、收益归因 | A 对 A′ 看适配作用，A′ 对 A′+B 看源方法在该系统中的增量；同时检查目标现象和整体效果、稳定性与成本 |
| 七、结论 | 搬运的是作用机制及其成立条件；流程不能保证一定找到有效 idea，需要可验证假设与否证条件 |

落点为 [迁移规范](../../RESEARCH_WORKFLOW.md) 与 [TRANSFER_PACKAGE 模板](../../topics/_templates/transfer_package.md)。与此前本地迁移技能基本一致，本轮新增了用户指定的飞书原文作为直接来源。

## 7. 研究记录的角色映射

WF03 第1章提到的文档角色在现有四层内组织，按需形成实际内容：

| 角色 | 当前映射/未来位置 |
|---|---|
| 论文笔记与原始论文 | `research/papers/<source>/`，分析包引用原文版本 |
| 文档总入口/index | 根 README、各层 README 与推进台账 |
| 已发现实验现象 | 实验 record/squeeze 保留原证据，Mode C 合并 P/F/M/E；需要跨实验索引时再建，不脱离来源复制结论 |
| 论文素材库 | 经过证据核验后在 topics 记录可用于论证的发现与来源；探索拼装不直接升级为论文贡献 |
| 最新实验分析与详细数据 | `experiments/<id>/` 的运行索引、record、squeeze 及汇总；“最新”通过索引指出，不覆盖旧报告 |
| 版本演化、关键决策 | `topics/decisions.md`、`topics/progress.md` 和候选版本 |
| 从实验到论文的宏观计划/写作读取清单 | 定题后在 topics 规划，列所需证据、实验和可用写作材料；目前尚未定题 |
| baseline 骨架及改造图谱 | 有实际 baseline 后在研究/代码说明中记录模块、接口、已知/未知、参考工作修改和消融 |
| 方案归档 | 按 Idea、迁移与实验计划版本保留，不删除被放弃的方案及原因 |

## 8. 多份材料之间的差异

- 较早章节允许随机组合发现意外；五技能协议和后面的迁移章节强调证据连接、条件和归因。保留两者：探索组合是找现象的试错，正式方案需走证据整合和独立验证。
- Q2 的单变量要求与“强交互需要组合对照”并不互相替代：先明确单因素作用，再对有依据的交互做专门设计，不能把同时改很多处的结果单归因于一个模块。
- 高引用 baseline、改造次数、a–d 论文等级等是原作者的经验分类，已在原文保留；它们不构成本项目论文价值、源码可得或录用结果的保证。
- Q3/Q4 对新颖性的经验表述与五技能核验标准同时保存；本项目继续以可定位来源、查新范围和实际验证判断。
- “1a-2b 未定义”这一旧缺口由 WF03 明确文本补齐；不修改旧来源或倒填旧记录。Q7 仍空白。
