# 代码层

当前没有实现代码，语言、依赖环境和部署方式尚未确定。这里为后续可复用能力预留，例如功率/性能采集、输入回放、任务调度和结果分析；按具体实验需要逐步建立模块。

研究实现须对应 [正式流程](../RESEARCH_WORKFLOW.md) 的 Idea/诊断方案：定位到关键模块后做最小改动，每次对照只改变一个关键研究变量，列出代码差异和其作用；不借实验顺带重构或堆叠模块。

## 放置原则

- 单次试验的启动、临时分析放在对应 `experiments/<experiment_id>/` 中。
- 多个实验共用的实现放在本层，实验目录通过入口调用，避免复制后各自漂移。
- 可复用配置结构、指标定义与数据格式随代码维护；固定某次试验的参数保存在实验目录。
- 实测设备接口和模拟接口说明各自边界；未核验的功能不假装返回真实硬件结果。

## 首次实现时补齐

说明运行环境、依赖安装方式、最短启动命令、输入输出格式和适用设备。验证先从配置解析、CPU 回放或小样本开始；需要 GPU 才能验证的行为明确记录目标机器和实际结果。

硬件、SLO 和评估口径沿用 [根规范](../AGENTS.md)；实现依据链接到 [候选题](../topics/candidates.md) 和具体实验计划。不要在尚未选定方向前创建无人使用的完整调度框架。
